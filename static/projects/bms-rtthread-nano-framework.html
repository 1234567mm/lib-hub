2.2 文件修改规则

规则一（改哪里）：自维护代码全部集中在 User/ 下。要定制第三方文件时，复制一份到 User/ 下改名自用（如 _template/board.c → User/bsp/rt_board.c），再在 CMakeLists.txt 里做"替换接线"，保持 Middlewares 原封不动。
规则二（不可随意改的文件）：cmake/stm32cubemx/CMakeLists.txt 和 Core/ 下所有文件在 CubeMX 重新生成代码时会被重写。Core 下只允许写 /* USER CODE BEGIN x */ 与 /* USER CODE END x */ 之间的区域（重生成时保留）；CMake 自定义内容全部写在根 CMakeLists.txt（标注 generated only once，永不被覆盖）。

3. CubeMX 生成框架：初始代码从哪里开始

3.1 两套框架的视角差（理解全局的钥匙）

本工程同时存在两套"框架视角"，它们在 main() 处汇合：

CubeMX 裸机视角
CubeMX 假设 main() 是程序入口：上电 → main() → 外设初始化 → while(1)。它把所有外设初始化（MX_*_Init）和用户代码都排在 main() 里。
RT-Thread 视角
RT-Thread 要求先启动内核（心跳、堆、调度器），再把 main() 当作一个普通线程的入口函数来调用——此时外设初始化天然发生在调度器启动之后。

两者的汇合方式：启动文件不再直接执行 main()，而是先执行 RT-Thread 的启动流程；内核起来之后，由名为 "main" 的线程去调用 main() 函数。于是 CubeMX 生成的所有代码一行都不用改，只是它们的执行时机从"裸机主流程"变成了"main 线程里"。

3.2 CubeMX 生成代码的初始化结构（main.c）

int main(void)
{
    HAL_Init();                  /* ① HAL 库基础设施：NVIC 分组、Flash 接口、TIM2 时基 */
    SystemClock_Config();        /* ② 时钟树：HSE→PLL×9 → SYSCLK 72MHz */
    MX_GPIO_Init();              /* ③ 各外设初始化，顺序由 .ioc 决定 */
    MX_CAN_Init();
    MX_USART1_UART_Init();       /*    PA9/PA10 控制台串口 */
    MX_USART2_UART_Init();       /*    PA2/PA3 RS485 串口 */
    /* USER CODE BEGIN 2 */
    BMS_SysInitialize();         /* ④ 业务总入口（User/bms/core/bms_app.c）*/
    /* USER CODE END 2 */
    while (1)                    /* ⑤ main 线程的主循环 */
    {
        LED 翻转;
        rt_thread_mdelay(1000);  /* 线程睡眠 1s，让出 CPU */
    }
}

3.3 USER CODE 区机制

CubeMX 生成代码时按 .ioc 配置重写整个文件，唯一的保留区是成对的 /* USER CODE BEGIN x */ … /* USER CODE END x */ 注释之间。因此对 Core/ 文件的一切修改（含中断处理函数、头文件引用）都必须写在这些区域内。

4.5 关键配置：GCC 入口接管

原理：Keil 的 ARMCC 编译器支持 $Sub$$main 语法，链接时自动把入口 main 换成 rtthread_startup——Keil 教程无需任何操作。GCC 没有该语法，RT-Thread 包改用 entry() 函数方案（components.c 第 156~163 行，注释注明 "Add -eentry to arm-none-eabi-gcc argument"）。本工程的启动文件默认 bl main，若不修改，上电将直接执行 main() 并完全绕过 RT-Thread：无调度器、无心跳、无 FinSH，首个 rt_thread_mdelay 永久阻塞。

配置方法：将 startup_stm32f103xb.s 中 Reset_Handler 末尾的 bl main 改为 bl entry（等效备选方案：在 rt_board.c 末尾添加 __attribute__((constructor)) 钩子调用 rtthread_startup()，该写法存于自维护文件中，不怕 CubeMX 覆盖）。

4.6 双时基并行结构

芯片内同时运行两个独立计时系统，职责分离、互不干扰：

SysTick
RT-Thread 心跳
rt_board.c: SysTick_Config(72M/1000) 装载 stm32f1xx_it.c: SysTick_Handler 响应 rt_os_tick_callback → rt_tick_increase
服务对象：调度器时间片、rt_thread_mdelay/睡眠、IPC 超时、软件定时器。每 1ms 使系统 tick +1。
TIM2
HAL 时基
HAL_Init → HAL_InitTick(TIM2) 装载 stm32f1xx_it.c: TIM2_IRQHandler 响应 HAL_TIM_PeriodElapsedCallback → HAL_IncTick
服务对象：HAL_Delay、HAL_GetTick、HAL 驱动内部超时（如 UART 等待标志）。
为什么分开：HAL 的延时/超时逻辑与 RTOS 调度使用同一计时源时会互相干扰（例如 RTOS 关调度器期间 HAL 超时失准）。CubeMX 启用第三方 RTOS 包时把 HAL 时基从 SysTick 挪到 TIM2，正是为了消除冲突——这也是为什么 SysTick 能完整让给 RT-Thread。

DMA 与 _IT 的关系：HAL 函数名后缀决定数据搬运方式——无后缀（轮询）、_IT（每字节中断搬运）、_DMA（DMA 控制器整块搬运，完成后才中断一次）。本工程 RS485 使用 _IT 逐字节收发，只需使能对应 NVIC 中断，无需配置 DMA；DMA 适用于大块报文（如 Modbus 帧）或高波特率场景。

7.2 周期业务线程模板（对应 BMS 采集 250ms 节拍）

static void bms_monitor_thread_entry(void *param)
{
    while (1)
    {
        BMS_MonitorTaskEntry();        /* 单次采集任务 */
        rt_thread_mdelay(250);         /* 周期 250ms，期间 CPU 让给其他线程 */
    }
}

static int bms_monitor_task_start(void)
{
    rt_thread_t tid = rt_thread_create("bms_mon", bms_monitor_thread_entry, RT_NULL,
                                       1024,   /* 栈：放 printf/排序等，1KB 起 */
                                       12,     /* 优先级：8~14 业务区 */
                                       10);    /* 时间片：同级轮转权重 */
    if (tid != RT_NULL) rt_thread_startup(tid);
    return 0;
}
INIT_APP_EXPORT(bms_monitor_task_start);   /* main 线程阶段自动执行，无需手动调用 */
配套调试手段：业务线程跑起来后，串口终端 ps 可观察所有线程的优先级与栈剩余、free 查堆水位、MSH_CMD_EXPORT(func, desc) 可把任意业务函数导出为串口命令在线触发——这是 RTOS 相对裸机最大的开发体验提升。

9.1 术语速查

术语解释
向量表 / 复位向量芯片上电时查询的"地址目录"，首项为栈顶地址，次项为复位后第一条代码（Reset_Handler）
.data / .bss已初始化 / 未初始化全局变量段；启动时前者从 Flash 搬初值，后者清零
tick（心跳）RTOS 最小时间单位（本工程 1ms）；延时与超时均以 tick 计数
ISR中断服务程序：硬件事件触发后 CPU 自动执行的函数
抢占式调度高优先级线程就绪即打断低优先级线程；同优先级按时间片轮转
线程栈 / 堆线程私有内存（局部变量、调用链）/ 内核动态分配池（rt_thread_create 等）
临界区rt_enter_critical/exit 之间不可被调度打断的代码段
自动初始化INIT_BOARD_EXPORT（main 前）/ INIT_APP_EXPORT（main 线程内）登记后自动执行，替代手工逐个调用
$Sub$$mainARMCC 语法：链接时以 rtthread_startup 替换 main 入口；GCC 无此语法，故需 bl entry 手动接管
