# blog-deploy

自动 git 提交并推送到 GitHub，触发 CI/CD 在线构建部署。支持**双轨发布**模式：同一内容同时存在于 blog（时间线展示）与 docs（知识库），**blog 与 docs 均为完整内容**（非摘要版）。

---

## 📐 blog ↔ docs 双轨关系（所有模块通用）

```
首页最新动态 (Blog)                         结构化知识库 (Docs)
    │                                              │
    │  blog/YYYY-MM-DD-slug.md                     │  docs/<模块>/<slug>.md
    │  （完整内容 + truncate + blog frontmatter）   │  （完整内容 + docs frontmatter）
    │                                              │
    └──→ 内容相同，仅 frontmatter 不同 ───────────→┘
```

**通用规则（适用于 stm32 / esp32 / sharing 干货分享 / 开发工具 等所有模块）**：

- **Blog**：`blog/YYYY-MM-DD-slug.md`，frontmatter 含 `title`/`description`/`authors: yamahoney`/`tags`/`date` + `<!-- truncate -->`，正文为完整内容
- **Docs**：`docs/<模块>/<slug>.md`，frontmatter 为 docs 风格 `id` + `title` + `sidebar_position`，**去掉** blog 的 `authors`/`tags`/`date` 与 `<!-- truncate -->`，正文与 blog 相同（完整内容）
- 各 docs 模块目录：
  - `docs/stm32/...`（基础知识/外设驱动/项目实战/入门教程）
  - `docs/esp32/...`
  - `docs/sharing/...`（干货分享）
  - `docs/开发工具/...`
- **干货分享特例**：`docs/sharing/` 侧边栏是 `autogenerated`，且首页 `docs/sharing/intro.md` 手动维护「笔记文章」列表——新增笔记必须**同时**在该列表追加相对链接 `[标题](./<slug>)`，否则侧边栏有但首页列表看不到

## 用法

```
/blog-deploy 修复DMA文章中的typo              # 单轨修复
/blog-deploy sync: 新增 SPI Flash 与内部 Flash  # 双轨发布（blog + docs 同步）
/blog-deploy feat: 新增 STM32 PWM 文章         # 单轨新增
```

## 双轨发布工作流（新增内容时使用）

适用于**新写一篇长文，同时希望在 blog 首页展示、docs 知识库完整阅读**的场景。

1. **创建 blog 版本** — 完整内容写在 `blog/YYYY-MM-DD-slug.md`，含 frontmatter（title/description/authors/tags/date）+ `<!-- truncate -->` + 完整正文
2. **复制到 docs** — 在对应知识库目录创建文件，如 `docs/stm32/stm32-basics/NN-slug.md`（或 `docs/sharing/<slug>.md` 等）
   - frontmatter 改为 docs 风格：`id` + `title` + `sidebar_position`
   - 去掉 blog 特有的 `authors`/`tags`/`date` 字段
   - 去掉 `<!-- truncate -->` 标记
   - **正文保持完整内容，与 blog 相同**（本仓库实际模式：不是摘要版）
3. **干货分享模块额外步骤** — 在 `docs/sharing/intro.md` 的「笔记文章」列表追加相对链接 `[标题](./<slug>)`
4. **运行 `npm run build`** 前置构建检查
   - 构建失败自动中止，不推送
5. **构建通过** → `git add -A && git commit -m "..." && git push`
6. 输出 GitHub Actions 构建链接

## 单轨发布工作流（仅更新 blog 或仅更新 docs 时使用）

1. 运行 `git status` 了解当前变更
2. 生成 conventional commit 消息
3. 运行 `npm run build` 前置构建检查
4. 构建失败自动中止，不推送
5. 构建通过 → `git add -A && git commit -m "..." && git push`
6. 输出 GitHub Actions 构建链接

## ⚠️ PowerShell 环境提交注意事项（本仓库已踩坑）

本仓库运行在 **Windows PowerShell** 下，git 操作有以下已知坑点，直接照此执行即可：

### 1. 多行 commit message 必须用变量承接 here-string

```powershell
# ❌ 错误：直接内联会报 "unknown switch"（@' 被当作参数解析）
git commit -m @'
sync: 标题
- 正文
'@

# ✅ 正确：先赋值给变量，再传给 -m
$msg = @'
sync: 标题

- 正文要点
'@
git commit -m $msg
```

### 2. push 被拒（远端落后）→ 先 rebase 再 push

```powershell
git pull --rebase origin main
git push origin main
```

`git pull --rebase` 的输出即使显示 `error:` 开头（PowerShell 把 git 的 stderr 当错误流），只要末尾有 `Successfully rebased and updated refs/heads/main` 即成功，可继续 push。

### 3. PowerShell 会把 git 的 stderr 输出误报为 "error"

`git push` 成功后 PowerShell 仍可能显示 `error: command exited: exit status 1` 或红色 stderr。**判断成功与否看输出内容**：
- 看到 `xxx..yyy  main -> main` 就是推送成功 ✅
- 看到 `Updates were rejected` 才是真的失败，需要 rebase

### 4. 提交前检查 `reasonix.toml` 是否被工具自动改动

调试命令会自动被追加进 `reasonix.toml` 的 `[permissions] allow` 列表。它**不属于发布内容**，提交前应还原：

```powershell
git checkout -- reasonix.toml   # 还原后 git status 应不再显示它
```

### 5. 双轨发布提交后核对 docs 侧边栏

若本次涉及干货分享等 docs 笔记，提交前在 `build/` 产物里核对侧边栏是否出现新文档（`docs/sharing/` 下 `autogenerated` 扫描）。也可直接用 grep 检查：

```powershell
$html = [System.IO.File]::ReadAllText("D:\1-QRS\0-Admin\lib-hub\build\docs\sharing\intro\index.html", [System.Text.Encoding]::UTF8)
# 检查 html 是否包含新笔记链接
```

## commit 类型

| type | 适用场景 |
|------|----------|
| `sync` | **双轨发布**：blog 摘要 + docs 完整内容同步新增 |
| `post` | 新增/更新博客文章（仅 blog） |
| `docs` | 更新知识库文档（仅 docs） |
| `fix` | 修复内容错误或断链 |
| `chore` | 配置/构建脚本变更 |
| `refactor` | 重构不改变内容功能 |

## ⚠️ 已知构建警告（不影响成功）

以下警告是 **Docusaurus 静态检查的已知行为**，构建结果仍为 `[SUCCESS]`，可正常部署：

| 警告内容 | 根因 | 状态 |
|---------|------|------|
| `blog/rss.xml` 断裂链接（所有页面均有） | footer RSS 链接指向完整 URL 即可消除（RSS 文件在链接检查后生成） | ✅ 已修复 |

### 自定义页面锚点注册指南

如果未来在 `src/pages/` 下创建自定义 React 页面并使用了 `to="#anchor"` 的同页跳转，需使用 Docusaurus 官方 API 注册锚点：

```jsx
import useBrokenLinks from '@docusaurus/useBrokenLinks';

function MySection() {
  useBrokenLinks().collectAnchor('my-anchor');
  return <h2 id="my-anchor">标题</h2>;
}
```

否则构建会报告 `[WARNING] Docusaurus found broken anchors`（不影响构建成功，但应修复）。

**如果构建输出中出现其他断裂链接**（以及未注册的锚点），必须修复后再推送，不能忽略。
